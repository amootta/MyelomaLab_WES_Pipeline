Myeloma Lab · UCL Myriad

Running the WES pipeline

Paired tumour–normal exomes in, then HLA and KIR typing, somatic consensus calls, neoantigens, clonality and mutational signatures out. Everything is driven by one command, ./wes.sh, and two files you edit: a config and a sample sheet.

GRCh38SGE + apptainernf-core/sarek 3.8.1mgp1000 · Nextflow 22.10.8

Part B · once per batch

Set up a batch

  1. cd ~/Scratch/MyelomaLab_WES_Pipeline
cp config/pipeline.config config/batch2.config
cp config/samples.tsv     config/batch2_samples.tsv

    In batch2.config, change two lines. Everything then writes to ~/Scratch/AMATTA/WES_tumor_batch2/.

    BATCH_NAME=WES_tumor_batch2
SAMPLES=$PIPELINE_DIR/config/batch2_samples.tsv

    Tell wes.sh which batch you're on (once per login):

    export PIPELINE_CONFIG=$PWD/config/batch2.config

  2. Tab-separated, one row per FASTQ pair (lane). Keep the header row.

    patientsamplestatussexlanefastq_1 / fastq_2crambam
    COS_005_001COS_005_001_PBMC0XX3…_PBMC_L3_1.fq.gz
    COS_005_001COS_005_001_BL1XX3…_BL_L3_1.fq.gz
    COS_005_001COS_005_001_BL1XX4…_BL_L4_1.fq.gz
    • status is 0 for the normal (PBMC/germline) and 1 for each tumour timepoint. Each patient needs one normal.
    • Two lanes of one sample share the sample name. Sarek merges them, so there's no need to merge by hand.
    • Use short names (<patient>_<timepoint>). Every output file is named after them.
    • sex defaults to XX. Change it per patient where you know it.
    • Already have crams or bams? Put the path in cram or bam and leave the FASTQ columns empty.
  3. ./wes.sh check
    reference + resources
  ok       REF_FASTA      ~/Scratch/GCA_000001405.15_GRCh38_no_alt_analysis_set.fa
  MISSING  PON            ~/Scratch/somatic-hg38_1000g_pon.hg38.vcf
sample sheet
  line 7: status must be 0 (normal) or 1 (tumour)
  6 patients, 6 normals, 12 tumours, 12 tumour/normal pairs

    Fix every MISSING path and every line it flags, until it ends with All good.

Part C · run it

Run order

Each command submits cluster jobs and returns straight away. Wait for the jobs to finish (qstat shows what's queued and running) before starting the next phase. Put DRY_RUN=1 in front of any command to see what it would submit without submitting.

1

Align and call variants 01 sarek

Full sarek run from FASTQs: alignment, base recalibration, Mutect2, Strelka, Manta, ASCAT, CNVkit. This is the longest step.
./wes.sh sarek fastq
waitfor the sarek_fastq job to finish
Convert recalibrated crams to bams. Samples that already have a bam are skipped.
./wes.sh sarek bams
Lab Mutect2 filters (VAF ≥ 0.01, MQ/BQ ≥ 20) plus a Funcotator MAF for each pair
./wes.sh sarek filter_mutect2
2

Everything that needs the bams run together

Somatic: Mutect2 + Strelka + VarScan consensus, Manta, Delly 02 mgp1000
./wes.sh mgp1000 somatic
Germline: DeepVariant small variants and fastNGSadmix ancestry, once per normal. It can run at the same time as somatic. 02 mgp1000
./wes.sh mgp1000 germline
HLA typing on each normal, three ways 04 hla
./wes.sh hla t1k
./wes.sh hla hlatyping     # OptiType + HLA-HD
./wes.sh hla hlala
KIR typing on each normal 05 kir
./wes.sh kir t1k
./wes.sh kir kircle
IG rearrangements and translocations for each pair 06 igcaller
./wes.sh igcaller run
Read and coverage QC for every sample. Qualimap reports on-target coverage over QC_TARGET_BED. 10 qc
./wes.sh qc fastqc
./wes.sh qc qualimap
3

Gather typing and consensus calls

After the HLA jobs: put every caller's HLA results in one place, then the optional comparison reports. The HLA report needs HLA_TRUTH set in the config.
./wes.sh hla collect
./wes.sh hla concordance   # optional
./wes.sh kir concordance   # optional
After mgp1000: variants called by at least 2 of the 3 callers. Only this batch's pairs are taken from the shared mgp1000 folder. 03 consensus
./wes.sh consensus vcf     # per-tumour VCFs: pVACseq, PyClone
./wes.sh consensus isec    # variant tables: signatures
After the QC jobs: one report with FastQC, Qualimap and sarek's own metrics 10 qc
./wes.sh qc multiqc        # QC/multiqc/multiqc_report.html
4

Downstream analyses

Neoantigens. The first command writes one HLA file per patient from the OptiType calls. Open those files and check the alleles before you run. 07 pvacseq
./wes.sh pvacseq hla
./wes.sh pvacseq run
Clonal structure across each patient's timepoints, from the consensus SNVs and ASCAT copy number 08 pyclone
./wes.sh pyclone run
Builds one MMSig input table, which you then run in R. Calls are hg38 and mmsig defaults to hg19, so set the genome. 09 signatures
./wes.sh signatures input
HLA class I loss of heterozygosity for each patient, from the collected HLA calls and ASCAT purity/ploidy. Check the inputs files before run. Each patient takes several hours. Details are in docs/LOHHLA.md. 11 lohhla
./wes.sh lohhla inputs     # LOHHLA/<patient>/input/
./wes.sh lohhla run
./wes.sh lohhla summary    # LOHHLA/LOHHLA_summary.tsv
Day to day

Keeping track

What has finished?

./wes.sh status
sample           type cram  bam   mut2f ascat cons.v hlaT1K ...
COS_005_001_PBMC N    +     +                       +      ...
COS_005_001_BL   T    +     +     +     +     .            ...

+ means the output exists, . means it's still missing, and a blank means that step doesn't apply to this kind of sample.

A job failed

  • Logs: ~/Scratch/<batch>/logs/<job>.o<id>.<task>. Array jobs have one file per sample.
  • Fix the cause, then run the same command again. The Nextflow steps (sarek, hlatyping, mgp1000, pVACseq) carry on from where they stopped.
  • ERROR: required input(s) missing before anything was submitted means the previous step hasn't finished, or a config path is wrong. The lines above the error name each missing file.

Good to know

  • Every batch shares the mgp1000 install, but each batch runs in its own mgp1000/ folder. The consensus step takes only the pairs whose tumour is in your sample sheet.
  • mgp1000 copies each bam with the read-group sample name fixed. Sarek's own bams are not changed.
  • If consensus vcf warns that a tumour has two VCFs, it was run through mgp1000 twice. Delete the one you don't want from mgp1000's output.
  • Other people's batches don't interfere with yours as long as each batch has its own config.
